### A1. Repo Standards (Backend)
- Endpoints de Actions usan FastEndpoints con `/api/v1`, `Tags("Actions")` y `Policies(PermissionClaims.Actions.*)`.
- Estilo CQRS-lite consistente: `ICommand<Result<T>>` + `ICommandHandler<,>`.
- Endpoints usan `Send.OkAsync` y `Send.ErrorsAsync(400)` con `Result<T>`.
- `Mapster` para mapear `Request -> Command`.
- Persistencia via `IApplicationDbContext` + EF Core.

### A2. Repo Standards (DB)
- Ruta SQL oficial para este requirement: `telemetric-api/scripts/*.sql` (decision `D-ACT-001-B1`).
- `RuleTemplateVersion.DefinitionJson` existe como `NVARCHAR(MAX)`.
- `RuleInstance` mantiene unicidad `(DeviceId, RuleTemplateVersionId)` y soft-delete/audit.
- Multi-tenant se aplica por `ClientId` en handlers de Actions.

### A3. Story Fit Check
- Need ACT-005 (storypack/spec): builder Scratch para 5 tipos de regla, validaciones de bloques, coherencia temporal `T <= W`, missing data policy (`INSUFFICIENT_DATA` / `HOLD_LAST_VALUE` con TTL), lifecycle (auto/latch + cooldown), y validacion de Email recipients.
- Reuso disponible:
  - FE rutas/vistas de Actions ya existen en `/actions` y `/actions/templates/:id`.
  - BE endpoints create/update template y create-from-device ya existen.
  - DB persiste `DefinitionJson`, `IsLatchMode`, `CooldownSeconds`.
- Gap implementacion (no bloqueante de plan):
  - UI actual sigue en `DefinitionJson` libre (textarea).
  - Validacion semantica DSL aun no esta aplicada en handlers/endpoints actuales.
- Conclusión: historia factible y desbloqueada para implementacion por fases.

### A4. Guardrails Confirmation
- Reuse-first para endpoints: discover -> equivalence -> reuse -> only-if-missing.
- Mantener ruta SQL en `telemetric-api/scripts/*.sql` (no abrir ruta nueva).
- No introducir acciones operativas fuera de Email en v1.

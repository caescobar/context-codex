### A1. Repo Standards (Backend)
- Endpoints de Actions usan FastEndpoints con `/api/v1`, `Tags("Actions")` y `Policies(PermissionClaims.Actions.*)`.
- Patron CQRS-lite consistente con `ICommand<Result<T>>` + `ICommandHandler<,>` en `Features/Actions/*`.
- Mapeo request->command con Mapster (`req.Adapt<...>()`) en endpoints de Actions.
- Convencion de respuesta: `Send.OkAsync` y errores via `Send.ErrorsAsync(400)` o `Send.NotFoundAsync` segun caso.
- Persistencia via `IApplicationDbContext` con filtros de tenant (`ClientId`) en queries de templates.

### A2. Repo Standards (DB)
- Ruta SQL vigente del requirement: `telemetric-api/scripts/*.sql` (decision `D-ACT-001-B1`).
- Modelo `ActionAttempt` ya persistido con `Status`, `Error`, `AttemptedAt`, soft-delete y checks de consistencia.
- Relaciones necesarias para ACT-006 existen: `ActionAttempt -> RuleInstance -> RuleTemplateVersion -> RuleTemplate`.
- Naming SQL alineado a estandar (`RuleTemplate`, `RuleInstance`, `ActionAttempt`) y constraints explicitas.

### A3. Story Fit Check
- Need ACT-006: historial de runs success/fail en `/actions` + runs asociados por template en `/actions/templates/:id`, separando contexto global vs template.
- Reuso disponible:
  - FE ya tiene rutas objetivo (`/actions`, `/actions/templates/:id`) y tab `runs` en template detail.
  - BE ya tiene modelo/tabla `ActionAttempt` y conteo de fallos por template (`failedRunsCount`).
  - OpenAPI incremental de Actions ya existe y puede extenderse sin crear artefacto paralelo.
- Gap detectado (implementable, no bloqueante):
  - No existe endpoint dedicado de listados de runs (global ni por template).
  - `/actions` hoy renderiza listado de templates, no landing con tabs Runs/Rules/Templates.
  - Tab `runs` en detalle de template hoy solo muestra contador y no historial detallado con error.
- Conclusion: historia factible y desbloqueada para implementacion por fases.

### A4. Guardrails Confirmation
- Reuse-first obligatorio para endpoints: discover -> equivalence -> reuse -> only-if-missing.
- No exponer estado interno de evaluacion del engine en UI (solo estado/error de `ActionAttempt`).
- Mantener contratos internos en ingles y copy UI en espanol.
- No crear rutas QA fuera del canon:
  - `contexto/work/features/acciones_modulo/04_test/ACT-006/phase-{phase_id}/`
  - `contexto/work/features/acciones_modulo/04_test/ACT-006/STORY_QA.md`
- Mantener OpenAPI incremental en `contexto/openapi/actions.yaml` (sin archivo alterno).

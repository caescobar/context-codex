### A1. Repo Standards (Backend)
- FastEndpoints en uso con rutas `"/api/v1/..."` y políticas por `PermissionClaims.*`.
- Patrón CQRS-lite vigente: `ICommand<Result<T>>` + `ICommandHandler<,>` en handlers.
- Mapeo request->command/query con Mapster (`Adapt<>()`) en endpoints.
- Respuesta uniforme por `Send.OkAsync` y `Send.ErrorsAsync`.
- Persistencia desde handlers vía `IApplicationDbContext` y `SaveChangesAsync`.

### A2. Repo Standards (DB)
- Coexisten EF mapping (`TelemetricDbContext`) y scripts SQL; para este requirement la decisión vigente fija `telemetric-api/scripts/*.sql`.
- Modelo base de Actions ya existe (`RuleTemplate`, `RuleTemplateVersion`, `RuleInstance`, `ActionAttempt`, `RuleCheckpoint`).
- Convenciones de auditoría/soft-delete (`IsActive`, `IsDeleted`, `CreatedAt`, `UpdatedAt`) están presentes.
- Restricciones de unicidad clave ya existen para versiones y asignación por device/version.

### A3. Story Fit Check
- ACT-003 requiere CRUD/list/detail de templates y versionado inmutable, además de superficies FE `/actions` y `/actions/templates/:id`.
- Reuse candidato BE: `Features/Actions/ResolveManual` como patrón de endpoint/handler; `IApplicationDbContext` ya expone DbSets de Actions.
- Reuse candidato DB: schema base de Actions ya creado; no se identifica delta SQL obligatorio para cumplir ACT-003.
- Gap actual: no existen endpoints de templates/versiones ni feature frontend de actions.

### A4. Guardrails Confirmation
- Reuse-first: verificar equivalencia de endpoints antes de crear nuevos.
- No inventar rutas SQL nuevas; mantener `telemetric-api/scripts/*.sql` si hubiera delta.
- UI en español y nombres internos/contratos en inglés.
- QA sólo en rutas canónicas:
